## 1. Adopt Prisma Migrate (supersedes ADR 0002)

The database is in sync with `schema.prisma` and the old migration history is
gone. This step baselines the current schema and switches future changes to
migrations.

1. Write `docs/adr/0003-prisma-migrations.md`:
   - Context: the project is being deployed; schema changes and data fixes
     need an ordered, reviewable history.
   - Decision: `schema.prisma` stays the source of truth, but changes are
     applied through migrations. `migrate deploy` runs before the new server
     starts. `db push` is limited to local prototyping.
   - Consequences: a `migrations/` directory returns; every schema change needs
     a migration file; rollback is still restore-from-backup.
   - Mark ADR 0002 as `Superseded by ADR 0003`.
2. Back up the database:
   `mysqldump --single-transaction --routines --triggers komet_db > komet_db_pre_migrations.sql`
3. Remove the inert history table. It has 15 rows from the deleted migration
   folders and would make `migrate deploy` fail with "migration applied but
   missing from the migrations directory".
   ```sql
   DROP TABLE _prisma_migrations;
   ```
4. Generate the baseline SQL and the lock file:
   ```bash
   mkdir -p prisma/migrations/0_init
   npx prisma migrate diff --from-empty --to-schema prisma/schema.prisma \
     --script > prisma/migrations/0_init/migration.sql
   printf '# Please do not edit this file manually\nprovider = "mysql"\n' \
     > prisma/migrations/migration_lock.toml
   ```
5. Convert the data repair into a migration and delete `prisma/data/`:
   ```bash
   mkdir -p prisma/migrations/20261105090000_academic_year_labels
   cp prisma/data/2026-academic-year-labels.sql \
     prisma/migrations/20261105090000_academic_year_labels/migration.sql
   rm -r prisma/data
   ```
   Keep the REGEXP guards so the statement is a no-op on databases that are
   already fixed.
6. Mark the baseline as applied on the existing database, then apply the data
   migration:
   ```bash
   npx prisma migrate resolve --applied 0_init
   npx prisma migrate deploy
   npx prisma migrate status
   ```
   `migrate status` must report the database is up to date.
7. Update `apps/server/package.json` scripts:
   - `db:migrate`: `prisma migrate dev`
   - `db:migrate:deploy`: `prisma migrate deploy && prisma generate`
   - `db:migrate:status`: `prisma migrate status`
   - Keep `db:push` for local prototyping only.
8. Update `README.md`, `apps/server/README.md`, and `AGENTS.md`:
   - Replace the `db push` workflow with `migrate dev` / `migrate deploy`.
   - Deployment order: backup → `db:migrate:deploy` → restart server.
   - Remove the "no migration history" and `prisma/data/` references.
9. Verify on a scratch database, not the live one:
   - Create an empty `komet_migrate_check` database.
   - Point `DATABASE_URL` at it and run `npx prisma migrate deploy`.
   - Confirm all tables exist and `npx prisma migrate status` is clean.
   - Drop the scratch database.
10. Verify the live database:
    - `npx prisma migrate status` → up to date
    - Row counts unchanged: 2022 / 1132 / 556
    - `pnpm verify`
